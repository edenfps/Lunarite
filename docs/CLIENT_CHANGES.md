# Client changes ledger

Every modification made to the working client `C:\Games\Huxley`, measured against the clean
install `C:\Games\Huxley_Clean`. That install is the base: its `HuxleyMMOGame.exe` (SHA-256 `916C8029…`) is
byte-identical to the edited client's oldest backup, `Binaries\HuxleyMMOGame.exe.bak`.

**Rule:** any new client change gets a row here in the same commit, with the script that applies it,
its backup and how to undo it. The no-client-patch rule still holds: each row below was a specific,
approved exception, and none of them is a precedent.

**Re-check:** `python -I tools/Compare-HuxleyClient.py` rewrites `analysis/client-diff.json`
(added / removed / changed files; logs and shader caches are skipped). Last run 2026-10-31: 237
added, 2 removed, 1,624 changed. Every entry is accounted for below.

## Player distribution (launcher)

Players do not get `C:\Games\Huxley` wholesale. They run our rebuilt `WZLauncher.exe`
(`tools/launcher`, bundle from `Make-LauncherBundle.ps1`) in a clean US install, and the Lunarite server's
patch server (`Network/PatchServer.cs`, port `HUXLEY_PATCH_PORT`, default 8090) delivers the files
listed in `patch/manifest.txt` from the patch payload `C:\Games\Huxley_PatchPayload`
(`HUXLEY_PATCH_ROOT`, set by `Launch-HuxleyServer.ps1`), never from this working client. The payload
is built by `tools/patches/build_patch_payload.py`: binaries, maps and UI packages are promoted from
this client; every `.ini` comes from the reviewed player copies in `patch/config/`
(`tools/patches/make_player_configs.py`), which keep the technical changes but reset the operator's
own settings (mouse sensitivity, console history, test name/team) to the clean install's. Player
copies also set `ConsoleKey=None` and `TypeKey=None` in `BaseInput.ini`, both `DefaultInput.ini` files
and `HuxleyMMOInput.ini` (the game rebuilds the last from the others), so launcher clients have no
developer console; GMs use a copy of the game started outside the launcher with `ConsoleKey=Tilde`.
`HuxleyMMOUser.ini` (resolution, graphics options) is never shipped. INIs that name the MMO server
are served with `m_strMMOIP` set to the address the launcher used. The launcher also deletes
`HuxleyMMOGame\Content\UI\HuxleyMMOUISkin_kor.upk` (config `<RemoveFiles>`) before starting the
game. A launcher on a Korean Windows is the exception: it starts the game with `-LANGUAGE=KOR`, keeps
that skin, and the patch server sends it the clean client's Webzen Korean files listed in
`patch/korean.txt` (every `Localization\KOR` file and the `_kor` skin) in place of the payload's
English-in-KOR text. **When a client change should reach players, add its path to `patch/manifest.txt` (an `.ini`
also needs a `patch/config/` copy) and rebuild the payload.**
